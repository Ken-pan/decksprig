For maintainers preparing subsequent releases:

1. Select/create the public repository, inspect its initial commit, enable secret scanning/push protection and private vulnerability reporting. Use the reviewed source candidate, not the dirty development directory. Review the public repository history and scan each new source candidate before packaging.
2. Confirm the selected repository/website/contact route in launch drafts. Public name screening and its country/database limits are recorded in [name-change.md](name-change.md); this is **not trademark clearance**, domain availability or worldwide registration advice. Check relevant software classes and markets before major spending or registration.
3. If hosting the browser demo, confirm its actual operator/privacy contact, log retention, provider production eligibility and billing alerts. Test the configured photo shutdown switch and inspect Netlify's deployment log to confirm the edge rule was applied. Per-IP throttling is not an absolute global spend cap; disable photo search if an operator has no acceptable hosting budget controls.
4. Treat Google OAuth production verification, Figma publication and native conversion on a user's machine as separate provider/device gates. They are optional for local editing.
5. Publish the reviewed source as a tagged early release, with a checksum and known format limits. Share only fictional demonstration content. Use the launch kit after URLs are real; never solicit votes or post to other people's channels automatically.

`private:true` prevents accidental npm publication. MIT permits commercial use and closed-source derivatives; keeping that flag does not prevent publishing a GitHub repository. This release is best-effort software, not a promise that all jurisdiction-specific rights or service obligations are cleared.

## Recovery release 0.1.8

Failed saves no longer claim that a browser recovery draft was retained without an acknowledged backup. Keep the current tab open to retry or export a copy. Recovery drafts expose an explicit branch choice used by both export and recovery; recovery creates a new document without changing the originals. Silent save requests now release their pending state without automatically replaying an uncertain write.

The repair is bounded to the independently checked failure and branch-selection paths. Real two-window write ordering, Node-service file-persistence UI, physical devices and actual storage-capacity exhaustion remain separate acceptance work. This release does not claim general storage reliability.
